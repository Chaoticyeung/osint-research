# osint-research

Claude Code / Agent Skill：用公开可得信息（OSINT）做**需要交叉印证和真伪判定**的结构化调研。
不是一张平台清单，而是一套**由问题推导记录来源**的收集与分析系统——经多轮对抗式 review 打磨，
把方法论纪律、中国渠道现实和合规边界都固化进了各参考文件。

## 三种模式

- **考证**：查证一个传闻/事件/机构是否真实、原貌如何（产出：竞争性假设矩阵 + 结论）
- **尽调**：合作/投资/交易前摸清一个人或公司的公开背景与风险（产出：红旗清单 + 背景档案）
- **溯源**：追一张照片/视频/一个说法的最初出处与真伪（产出：溯源链条 + 真伪判定）

共用一个子流程 **follow-the-money**（穿透空壳、追资金与控制关系），考证和尽调都可调用。

## 贯穿全库的十三条核心纪律

1. 从问题推导记录来源，不从平台清单出发
2. 开工先写两级调查纲目（大纲 + 细目），它管"要覆盖哪些面"，收集矩阵管"该去谁那里取证"
3. 证明力看来源对该主张的直接获取能力，不看官方/民间身份
4. 缺席只在覆盖了相关记录产生者后才算证据
5. 评级逐条打、不预设、不机械数数；信源评级 ≠ 结论置信度
6. 区分真实性缺口与覆盖缺口：前者找更可靠的源，后者找位置不同的源；数来源位置不数来源条数
7. 关键事实落到一手原文、摘录逐字抄；工具生成的页面概述不是证据
8. 对称怀疑，动机只定"查什么"不定真假
9. 结论分三层（已证事实 / 分析推断 / 内部待核）+ 分场景证据门槛
10. 涉个人：相关必要最小，不为猎奇建完整画像；私人事项过真实性/相关性/比例性三重门槛
11. 访问性动态测试、不绕过访问控制、验证码由用户完成
12. 每份交付必写覆盖声明——"根本没查"与"查了但没结果"分开写
13. 交付分版本、工具条件式、诚实标注边界

## 合规边界

仅用公开合法渠道；不碰非公开/泄露数据、不绕过访问控制、不做无正当目的的个人画像。
涉及在世个人时受《个人信息保护法》约束（目的明确、范围最小、合理范围处理），产出为供人判断的
风险线索，不构成对个人的最终判定。
